# 数据来源说明（Data Provenance Statement）

> 本文档说明 CyberGuard 平台中**每一项数据从哪来、是真实的还是模拟的**。
> 这是本作品对评审与使用者的**透明度承诺**：我们不会把模拟数据当成真实数据来展示，
> 也不会把真实数据的能力说得比实际情况更大。

---

## 一、为什么需要这份声明

网络安全的可视化作品有一个常见的信任问题：**观众无法分辨屏幕上的数字是采集来的还是编出来的**。

本作品采取的做法是**明确标注每一项数据的来源与生成方式**：

- 界面上带 **「模拟」** 标记的数据，均为内存沙箱生成，不来自任何真实网络
- 界面上带 **「实时采集」** 标记的数据（注：当前版本尚未引入，见第四节规划）才是真实主机计数器
- 真实数据库记录（日志、告警、黑名单）在页面上不做标记，因为它们是真实持久化数据

我们借用开源社区（如 NIDR 平台）的通行做法：**使用样本/模拟数据是可以的，
但必须说清楚哪些是样本、并保证处理代码是真的、可以对接真实数据源。**

## 二、真实数据（真实持久化 + 真实算法）

| 数据项 | 存储 | 来源 | 是否可对接真实环境 |
|---|---|---|---|

| 用户与权限 | SQLite `users` 表 | 真实账户体系，密码 PBKDF2-SHA256 哈希 | ✅ 真实能力 |

| **主机 CPU 占用** | 内存滚动窗口 | **psutil 读取操作系统真实计数器** | ✅ 真实采集 |
| **主机内存占用** | 内存滚动窗口 | **psutil 真实计数器**（含已用/总量 GB） | ✅ 真实采集 |
| **磁盘 IO 速率** | 内存滚动窗口 | **psutil 累计计数器差值** / 实测时间间隔 | ✅ 真实采集 |
| **网卡吞吐** | 内存滚动窗口 | **psutil 累计计数器差值**，换算为 Mbps | ✅ 真实采集 |

| **接口平均耗时** | 内存滚动窗口（最近 200 次） | **服务端 `after_request` 钩子真实测量** | ✅ 真实能力 |

**关键说明**：5 条暴力破解检测规则（IP 高频失败、账号多 IP 撞库、高频失败伴随零星成功、
字典攻击、慢速暴力破解）采用的是**真实的滑动窗口与双指针算法**，
其判定逻辑不依赖数据是模拟还是真实。把 `log_generator` 换成真实的认证日志采集器，
检测引擎可以原样运行。

### 关于主机指标的采集实现细节

真实的系统指标不是"调一下 psutil 就有数"，本作品处理了四个关键点：

| 要点 | 说明 |
|---|---|
| **非阻塞采样** | `cpu_percent(interval=None)` 返回"距上次调用以来"的平均占用率；**不能**传 `interval=0.1`，那会阻塞 100ms 并打乱 1.5 秒的推送节奏 |
| **首次采样丢弃** | `cpu_percent` 首次调用恒返回无意义的 0.0，必须丢弃 |
| **累计值做差值** | `disk_io_counters()` / `net_io_counters()` 返回的是开机以来的累计字节数（本机实测累计读写 193 GB / 126 GB），必须保存上次值、算差值、除以**实测**时间间隔得到速率；不能假设间隔恒为 1.5 秒 |
| **中位数平滑** | 原始读数抖动明显，直接上屏会闪烁；用 7 点中位数窗口（比均值更抗尖峰） |
| **逐项降级** | 任一项 psutil 调用失败（权限、平台差异）都单独标记为不可用，不让采样异常中断后台主循环 |

### 关于「攻击浪潮」的说明

攻击的产生不是恒定速率的随机过程，而是按**四阶段状态机**推演：

```
平静期（1.5~3.3 分钟）→ 攀升期（30~60 秒）→ 突袭期（1~2 分钟）→ 消退期（45~90 秒）→ 平静期 …
```

每个阶段有自己的出攻击速率（平静期 0.8 个/分钟，突袭期 70 个/分钟），
一轮完整浪潮约 **4~7 分钟**。这样设计的原因是：真实 DDoS 是**事件型**的，
大部分时间静默、来的时候集中爆发；而恒定速率会让"看 10 秒"和"看 10 分钟"
得到完全一样的观感，反而不真实。

导航栏的阶段徽章会实时显示当前处于哪个阶段以及剩余时长。
**平静期画面安静是正常现象，不是系统故障。**

所有浪潮参数集中在 `config.py` 的 `ATTACK_WAVE` 中，可在现场直接调整以演示
"参数如何影响攻击节奏"。

### 关于「系统健康度」的特别说明（已更新）

**原状态**：首页曾有 5 条系统健康度指标（CPU、内存、网络吞吐、连接池、磁盘 IO），
它们是按模拟负载派生的展示值 —— 五条指标全部由一个 `system_load` 变量乘固定系数得出，
因此永远等比例同步移动，属于典型的"看起来专业、实则编造"。

**现状**：这些编造值**已全部移除**，改为：

| 原编造项 | 现在 |
|---|---|
| 系统负载 = `30 + 沙箱带宽/20` | **删除**。改为主机 CPU 占用，由 psutil 真实采集 |
| 5 条健康度进度条 | **删除**。改为「主机资源」卡片，6 项全部真实采集 |
| 「清洗中」= `活跃攻击数 × 0.2`（魔法数字） | 改为沙箱内**按状态真实统计** `cleaning_count` |
| 「平均响应时间」= `Math.random()*5+2` | 改为 `after_request` **真实测量**的接口平均耗时 |
| `last_24h_attacks` 实为当前活跃数 | 改为按**时间戳队列真实统计** 24 小时窗口内的事件数 |

因此本作品**当前不存在任何编造指标**：每一项数据要么是真实采集/真实算法产出，
要么是内存沙箱的模拟推演，且都在界面上标注了来源。

> 需要说明的是：真实主机指标可能出现"不好看"的读数（例如开发机内存占用长期在 85% 左右）。
> 这是真实系统的本来面貌，我们**刻意不做修饰** —— 被修饰过的真实指标就又变回了假数据。

## 五、读者如何自行验证

本作品的透明性是可验证的，不需要信任我们的说法：

1. **验证模拟器不发包**：`utils/ddos_simulator.py` 全文无 `socket`、无 `scapy`、
   无 `subprocess`、无任何网络调用；只有 `random` 与 `datetime`。
2. **验证攻击源 IP 不指向真实资产**：`git grep -n "203\.0\.113\|198\.51\.100\|192\.0\.2"`
   可见所有攻击源 IP 均取自 RFC 5737 文档保留段。
3. **验证检测算法真实**：`utils/detector.py` 中规则 1、3 的滑动窗口实现可独立阅读与测试；
   `tests/test_all.py` 提供了规则触发的自动化测试。
4. **验证封禁真实生效**：把任意非回环 IP 加入黑名单，再以该 IP 发起请求，
   会收到 403 与拦截页（回环地址 127.0.0.1 出于自救考虑永不拦截）。

## 六、一句话总结

> **检测逻辑是真的，检测数据是模拟的；**
> **数据库与权限是真的，攻击态势是沙箱推演；**
> **不真实的部分我们标注出来，而不是让它看起来像真的。**
