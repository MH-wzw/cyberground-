# 告警邮件通知 — 使用与配置指南

> 功能定位：补齐安全运营闭环中「**告警触达**」这一环。
> 当没有人盯着大屏时，把达标的高危告警推送到值班人邮箱。
>
> 入口：登录后导航栏「📧 通知配置」，**仅管理员可见与可访问**。

---

## 一、五分钟配置好

### 第 1 步：添加收件人

进入「通知配置」页 → 收件人管理 → 填写邮箱与接收等级。

| 字段 | 说明 |
|---|---|
| 邮箱 | 告警接收地址，支持任意邮箱 |
| 备注名 | 如「值班A」，便于识别 |
| 接收等级 | **仅高危** / 中危及以上 / 接收全部 —— 支持给不同值班人设置不同阈值 |

> 可以不添加收件人先看功能，但**没有收件人时告警不会发送**，
> 投递记录里会显示「👥 无收件人」。

### 第 2 步：配置 SMTP

以常见的几个邮箱为例：

| 邮箱服务 | SMTP 服务器 | 端口 | 加密方式 | 密码填什么 |
|---|---|---|---|---|
| QQ 邮箱 | `smtp.qq.com` | 465 | SSL/TLS | **授权码**（非登录密码） |
| 163 邮箱 | `smtp.163.com` | 465 | SSL/TLS | **授权码** |
| Gmail | `smtp.gmail.com` | 465 | SSL/TLS | **应用专用密码** |
| Outlook | `smtp.office365.com` | 587 | STARTTLS | 账户密码或应用密码 |
| 企业自建 | 按管理员提供 | 25/465/587 | 视配置 | 视配置 |

**关键点：国内主流邮箱需要先在网页端开启 SMTP 服务并获取「授权码」，
不能用登录密码。** 这是最常见的配置失败原因。

发件人（From）建议填写成 `CyberGuard <你的邮箱@example.com>` 的形式，
收件端显示更清晰，也更容易被判定为非垃圾邮件。

### 第 3 步：点「发送测试邮件」验证

这是整套功能**可验证性**的关键设计：点一下，邮件要么真的到了，
要么明确告诉你失败原因（连接被拒 / 认证失败 / 超时）。

**配置完成前不要跳过这一步。** 真实的 SMTP 配置很容易因为授权码、
端口或加密方式不匹配而失败，而这个按钮能在几秒内给出答案。

### 第 4 步（可选）：用环境变量注入凭据

如果不想把凭据存进数据库，可以用环境变量（**优先级高于页面配置**）：

```bat
set CYBERGUARD_SMTP_HOST=smtp.qq.com
set CYBERGUARD_SMTP_PORT=465
set CYBERGUARD_SMTP_USER=your@qq.com
set CYBERGUARD_SMTP_PASS=你的授权码
set CYBERGUARD_SMTP_FROM=CyberGuard <your@qq.com>
set CYBERGUARD_SMTP_TLS=1
```

页面上会把当前生效的环境变量名列出来，便于核对。

## 二、通知规则：为什么默认值是这样

### 2.1 三层防护对抗「告警疲劳」

**这不是过度设计，而是必须的。** 本系统的攻击浪潮在突袭期的告警速率
实测可达 **70 条/分钟**。如果每条都发一封邮件，一小时内收件箱就被淹没——
这在安全运营中叫 **告警疲劳（alert fatigue）**，
其真实后果是值班人直接关闭通知，**反而漏掉真正的高危事件**。

| 层 | 默认值 | 作用 |
|---|---|---|
| **去重** | 同源 IP + 同类型，5 分钟内只发一次 | 把 70 条压到个位数 |
| **限流** | 每 5 分钟最多 3 封 | 硬上限 |
| **聚合** | 12 秒窗口内的告警合并为 1 封 | 把 N 封压成 1 封 |

配置页顶部会显示**抑制率**——例如「评估 8 条 / 实际投递 3 封 / 抑制率 62.5%」。
这个数字直接说明告警疲劳防护起了多大作用。

### 2.2 静默时段

默认 `22:00-08:00`，期间**仅放行高危**。

设计依据：非工作时间的推送涉及**员工休息权**，真实企业普遍设置静默时段。
如果不需要，把该字段清空即可关闭。

### 2.3 最低通知等级

默认「仅高危」。如果你的场景需要关注中危，
可在配置页调整为「中危及以上」——但要注意邮件量会显著增加。

## 三、投递记录：回答「为什么我没收到邮件」

每一次**本该通知**的告警都会留下记录，**包括被跳过的**：

| 状态 | 含义 |
|---|---|
| ✅ 已投递 | 邮件已成功发出 |
| ❌ 投递失败 | SMTP 出错，说明栏给出具体原因 |
| ⏸ 已去重 | 同源同类型告警在窗口内已通知过 |
| ⏸ 已限流 | 达到每窗口投递上限 |
| 🌙 静默跳过 | 处于静默时段且等级未达放行标准 |
| ⬇ 低于阈值 | 该告警等级未达通知要求 |
| 👥 无收件人 | 收件人列表为空 |
| ⚙ 未配置 SMTP | 缺少服务器地址或发件人 |

**这张表是"可审计"的体现**：任何一次"我觉得该收到邮件但没收到"都能在这里找到答案。

## 四、邮件里有什么、没有什么

通知邮件会经过第三方邮件服务器传递，因此遵循**最小必要原则**：

| 包含 | 不包含 |
|---|---|
| 告警时间、类型、风险等级 | 完整登录日志 |
| 来源 IP、来源国家 | 用户名 |
| 峰值带宽、目标服务端口 | User-Agent |
| 处置状态（已拦截 / 清洗中 / 攻击中） | 内网拓扑信息 |

邮件同时提供**纯文本**与 **HTML** 两种格式，并在页脚注明本邮件由系统自动发送。

## 五、本地存底：没有 SMTP 也能看邮件

每封邮件同时会在项目根目录的 `sent_emails/` 下存一份 `.eml` 文件。

**为什么需要它**：演示或测试环境往往没有可用的 SMTP 服务器。
有了本地存底，可以用任意邮件客户端（Outlook / Foxmail / Thunderbird）
直接打开 `.eml` 文件，查看**真实生成的邮件内容**。

这把「日志说发了邮件」变成了「邮件就在这儿」——延续本项目的数据透明原则。

## 六、安全设计

| 项 | 措施 |
|---|---|
| **权限** | 通知页面与全部 API **仅管理员**可访问（服务端强制，非前端隐藏） |
| **凭据保护** | SMTP 密码**永不**以明文回显；留空或保持 `********` 表示不修改 |
| **权限影响面** | 能改收件人意味着"能把告警外发到任意邮箱"，因此该组接口必须是管理员专属 |
| **失败隔离** | 邮件发送失败**绝不影响**告警生成与大屏展示（异步 + 超时 10 秒） |
| **不阻塞主流程** | SMTP 投递由后台线程完成，告警落库后立即返回 |

## 七、答辩演示脚本（约 3 分钟）

1. **打开「通知配置」页** —— 展示收件人、SMTP、规则三个区块
2. **点「发送测试邮件」** —— 手机/电脑当场收到，证明链路是通的（而非只是"写了个日志"）
3. **回到「登录日志」页，点「执行检测」或「引燃一波攻击」**
4. **邮件到达** —— 注意收到的是**一封聚合摘要**，而不是几十封
5. **回到「通知配置」页看投递记录** —— 展示「评估 N 条 / 实际投递 M 封 / 抑制率 X%」
6. **讲解三层防护与静默时段** —— 这是"告警疲劳"这个真实痛点的工程答案

**第 5 步最有说服力**：它把"我们做了去重和限流"从一句话变成了一个可验证的数字。

**备用方案**：若现场网络无法连外网 SMTP，可展示 `sent_emails/` 下的 `.eml` 文件，
用邮件客户端打开给评委看真实邮件内容。

## 八、常见问题

**Q：测试邮件提示"认证失败"怎么办？**
A：国内邮箱必须使用**授权码**而非登录密码；并确认已在邮箱网页端开启 SMTP 服务。

**Q：提示"连接被拒绝"或超时？**
A：多为端口与加密方式不匹配。465 配 SSL/TLS，587 配 STARTTLS；也可能是网络出口被封。

**Q：收不到邮件但记录显示"已投递"？**
A：检查垃圾邮件箱。建议把发件人加入白名单，或在 SMTP 配置里使用完整域名地址。

**Q：告警很多但邮件很少，是不是坏了？**
A：这正是设计目标。看投递记录里的「已去重 / 已限流」计数即可确认。
若要临时放宽，调大「限流」与「去重窗口」参数。

**Q：能否只让某个人收到高危？**
A：可以。在收件人列表里单独设置该邮箱的「接收等级」为「仅高危」。
